# Ace 原生入口与实际 XNU 预检

`ace/native-loader` 已把原生 ARM64 Image 入口接到实际 Ace 内核，串联
即时 CPU 采样、FDT 内存、平台/ADT 检查和精确段复制器，再跳入 XNU。
此前 `ace/xnu-loader` 的合成接收器仍是独立夹具，新入口不使用它。

目前仅有模拟环境中的原生执行结果，手机未执行这个 Image。它没有
iOS 根文件系统或可运行的 MTK 存储、显示、触摸驱动，不是可用 iOS。

## 启动路径及前提

入口要求 EL1 和 MMU/D-cache/I-cache/大端关闭，在任何 Image 数据写入
前检查装载范围、页对齐、固定 FDT 地址及最大 FDT 范围分离。随后屏蔽
DAIF，清理 BSS/工作区/64KiB 栈，建立 SP_EL1 和 EL1 异常向量。

C 入口取得即时 CPU 状态、解析 FDT、建立整个 Image 的内存排除策略，
并检查 Image 与固件保留区、动态分配域、initrd 冲突。它核对规范 ADT，
按真实段长度复制内核并清零 BSS，放置 ADT/BootArgs。再次采样 CPU、
核对栈哨兵后，执行屏障和指令缓存失效，携带物理 BootArgs 跳入 XNU。
后续 16K 页表由实际 XNU 设置。

固件必须已提供初始 Image RAM；数值范围不能证明所有权。原生阶段是
调用约定，不是软件自动发现的事实。其他核心、DMA、固件保留和一致性
仍需实际评估。可选 pmsg 依赖单独建立的 ECC0/type0/单写者普通 RAM
契约，只追加已有 DBGC 环，不初始化未知签名。进入日志验证前的失败
只有易失 Image 记录。XNU 替换 VBAR 后，本入口不再追踪其异常。

`ACENAT01` 记录为32个 LE uint64，包括版本、阶段、错误、FDT/Image/
载荷地址、内核/BootArgs/ADT 地址、CPU 值、日志状态、异常寄存器、
排除区、栈哨兵和 FDT 统计。阶段1–7依次为 C 入口、CPU、FDT、内存
策略、计划、物化、即将跳转；98表示本入口捕获异常。

## 产物和结果（2026-10-20）

内核仍为成功 CI `39288876908` 的实际 Ace 产物，SHA256
`e3772e867b64b1777488b9e2cf3ca1d5a431a4c7f543b106354d8fe05d98652a`。
原生 Image 为17317888字节，SHA256
`2139b81b057812fdb14b6871812359c69e8fd430681743781a6f27ad48b3c187`。
位于私有 `research/ace-native-entry-20261020/image-v2/`。它是 raw
Image，尚未封装 Android boot_b，没有新的分区写入授权。

七个 QEMU Cortex-A55 用例通过：EL2、错误 FDT 地址在 BSS 写入前拒绝；
62.5MHz 时基、无效 pmsg 在目标写入前拒绝。预置的内核段目标范围和
日志保持不变；没有逐字节检查整个3GiB管理窗口。三个成功装载地址为
`0x40080000`、`0x42000000` 和此前手机观察到的 `0x40000000`。
分离重定位用例覆盖旧 Image，检查是否错误依赖旧地址。

成功用例复制并执行实际 XNU 前11条指令，核对 BootArgs 读取寄存器。
全部10段文件、966656字节 BSS、段间空隙、ADT 和完整16KiB BootArgs
页均已比较，pmsg 保留原生标记和记录。这里没有使用合成接收器。

另一个测试到达实际 `_arm_init` 并单步执行其首条指令：

| 项目 | 值 |
|---|---|
| `arm_init` PC → 单步后 | `0xfffffe0007b2350c` → `0xfffffe0007b23510` |
| BootArgs KVA | `0xfffffe000811c000` |
| TCR_EL1 | `0x226511a511`，TG0/TG1 均为16K |
| TTBR0 / TTBR1 | `0x14117c000` / `0x141180000`，均16K对齐 |

这证明模拟 CPU 配置下实际内核越过了早期16K页表设置。QEMU CPU
cntfrq 明确配置为13MHz；手机 FDT 是夹具，模拟 GIC/外设不同于 MTK。
IRQ、存储、显示、触摸、用户空间和手机上的 XNU 均未验证。主动
MMU/cache/大端开启的汇编拒绝分支尚未逐项执行测试。

开发失败记录均保留：首次缺输出父目录；严格对齐编译需要真实 memcpy
导致初次链接失败，现已提供 freestanding 字节复制实现。第一次试图
通过 GDB 写 CNTFRQ 未生效，时基检查正确拒绝；改用本机 QEMU 公布的
CPU cntfrq 属性后才通过。

完整主机回归197项通过，44.212秒。构建/错误、内存转储、GDB命令、
C入口寄存器和哈希保存在私有 `research/ace-native-entry-20261020/`。
当次验证器源码已归档；之后只新增调试器输入类型/路径验证，未改变
被测试的 Image。

## 下一步

本轮手机仅作 USB 只读检查：在线、Android 已启动、SELinux Enforcing。
没有重启、模块加载或分区写入，既有 boot_b 诊断及备份保持。
下一步需为 XNU 自身增加最早入口日志，结合完整内核 CI 核对，再制作
具体可回滚的 Android 启动分区试验镜像。指定分区写入须另行确认，
这里的模拟结果不能作为 iOS 真机启动成功。
